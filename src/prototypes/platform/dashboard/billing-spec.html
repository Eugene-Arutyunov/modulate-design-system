States (every data component)

StateRendering
LoadingDS skeleton (.m__skeleton) shaped like each widget: stat (number + rows), actions (text + two buttons), rows (summary rows + button), lead-button (sentence + button), and the history table with its real headers and dividers. Usage charts load in place: the chart’s own grid without data or tick labels, pulsing with the skeleton animation. Title stays visible; tags and banners are hidden until data arrives. Screen-reader text “Loading…”.
EmptyA new account, not an abstract placeholder. Balance shows only 0.00 (Metered: the full 100,000.00 included credits with “0% of 100,000”, next invoice and commitment, since a new Metered account starts with them); the Buy Credits and Apply Credit Code buttons stay at the card bottom. While the card is loading or failed to load, the buttons and the view-only note are hidden for every customer type: only the title and the skeleton or the “Couldn’t load data” placeholder show. Auto Top-Up is Off with Enable Auto Top-Up. Alerts keeps its rows: thresholds read “No thresholds yet.”, Recipients keeps “Notify all admins and recipients from this list.”, every button still reads Edit. Billing History keeps the table headers with one centered .m__table-empty row naming what will appear for the customer type; Filter and Export are hidden since there is nothing to filter. Usage: the table keeps its headers with “No requests yet…”, the charts stay in place with their axes and grid and no data.
ErrorOne pattern for every widget, DS .m__widget__placeholder: the same centered sentence everywhere, “Couldn’t load data”, in the caption colour (not red), with a Try again secondary outline S button under it that retries only that block. Tables and charts use the .L size (4rem, same as .m__table-empty); other widgets 2rem. With a button the bottom padding is larger (3rem, .L 5.25rem), so the group sits optically centred. Filter and Export are hidden.
Page errorWhen every request fails, the widgets are not shown one by one: below the page title and lead there is a single widget with .m__widget__placeholder.L, “Couldn’t load data” and one Try again that reloads the whole page (all skeletons, then content). Banners are hidden. The block is at least 18rem tall. It has no title, so its caption and button stay in the geometric middle. Placeholder captions (empty and error) have no full stop at the end. Per-widget Error is for a partial failure, when the rest of the page did load.

Banner matrix

Banner copy is one or two short sentences: what happened and what it means for usage. The button says what to do, so the text does not repeat it; credit prices and rates are not quoted in banners (the Metered rate is a row in the balance card once included credits are used up).

Percentages are measured against the current allocation: the period allocation plus top-ups (Contracting), the last top-up (Pay/Go), or included credits (Metered).

Roles

Account admins can change settings, top up, and follow Stripe links. Everyone else sees the same data read-only:

  • Add, Edit, Remove, Save, Top up and Stripe actions are removed, not disabled, so there are no dead controls.
  • Actions a viewer can’t take are simply hidden: no “only admins can…” notes in their place. This includes the banner buttons; a view-only banner keeps its text (and the cross on info banners).
  • Exception: the balance card shows “Only your organization’s admins can buy credits.” in place of its buttons, so the missing buttons are explained.

Responsive

  • ≥ 900px: status row 3fr / 2fr; lower row two equal columns.
  • < 900px: every card is full width in the order: banner → balance → alerts → Auto Top-Up → history.
  • < 768px: the sidebar is hidden (DS dashboard rule); the history table stacks rows below 640px.
  • < 640px: tables become stacked label/value rows (data-label); banner actions move under the text.
  • < 520px: top-up presets stack full width.

Stripe entry points (in scope)

  • Pay $X on Top-up opens Stripe Checkout.
  • Update Payment Method (failed Auto Top-Up) and Manage payment methods ↗ open the Stripe customer portal.
  • Buttons never carry an arrow; only inline text links to Stripe show ↗. Both open in a new tab. After returning, the page refetches balance and history.

Later (post-MVP), with a placeholder in the UI

  • Auto Top-Up on a set date: a muted “Later” row in the Auto Top-Up card.
  • Overage spend cap: a muted “Later” row under overage alerts.
  • CSV export of usage: caption in the Usage tab toolbar.
  • Card expiry banner, account pricing display, and auto top-up for Contracting: no UI yet.

Open questions for product

  1. Contracting: do top-ups count towards the “% used” base, or does the % only track the monthly allocation? The prototype includes them.
  2. Pay/Go: should the 75% / 90% banners show at all while Auto Top-Up is on and healthy? They are informational here; we could suppress them.
  3. Can view-only members be alert recipients, and can external addresses be added (the prototype allows both)?
  4. Metered overage alerts: fixed amounts only, or also a percentage of the commitment?
  5. How are credit codes positioned for Contracting and Metered customers? The prototype keeps Apply Credit Code under Grants for admins.
