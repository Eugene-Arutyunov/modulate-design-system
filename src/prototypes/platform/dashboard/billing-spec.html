States (every data component)

StateRendering
LoadingSkeleton shaped like the content (stat / chart / table rows / lines). Title stays visible; tags and banners are hidden until data arrives. Screen-reader text “Loading…”.
EmptyCaption-colored sentence explaining what will appear and when, plus the primary action where one exists (e.g. Add alert, Add payment method).
ErrorSentence in --m__error that says what failed and, where true, that it doesn’t affect usage, plus a Try again secondary outline S button that retries only that block.

Percentages are measured against the current allocation: the period allocation plus top-ups (Contracting), the last recharge (Pay/Go), or included credits (Metered).

Roles

Account admins can change settings, top up, and follow Stripe links. Everyone else sees the same data read-only:

  • Add, Edit, Remove, Save, Top up and Stripe actions are removed, not disabled, so there are no dead controls.
  • Settings shows a “View only” notice at the top, and form fields are disabled.
  • Where a viewer is blocked (usage stopped, failed recharge), the banner explains who can act: “Ask an account admin to top up.”

Responsive

  • ≥ 900px: status row 3fr / 2fr; lower row two equal columns.
  • < 900px: every card is full width in the order: banner → balance → side card → balance chart → history.
  • < 768px: the sidebar is hidden (DS dashboard rule); history tabs scroll horizontally without wrapping.
  • < 640px: tables become stacked label/value rows (data-label); banner actions move under the text.
  • < 520px: top-up presets and Pay stack full width.

Stripe entry points (in scope)

  • Pay $X ↗ on Top-up opens Stripe Checkout.
  • Update payment method ↗ (failed recharge) and Manage payment methods ↗ / Change in Stripe ↗ open the Stripe customer portal.
  • Add payment method ↗ appears in the empty auto-recharge state.
  • External links carry a ↗ and open in a new tab. After returning, the page refetches balance and history.

Later (post-MVP), with a placeholder in the UI

  • Recharge on a set date: a muted “Later” row in the auto-recharge card.
  • Overage spend cap: a muted “Later” row under overage alerts.
  • CSV export of usage: caption in the Usage tab toolbar.
  • Card expiry banner, account pricing display, and auto top-up for Contracting: no UI yet.

Open questions for product

  1. Contracting: do top-ups count towards the “% used” base, or does the % only track the monthly allocation? The prototype includes them.
  2. Pay/Go: should the 75% / 90% banners show at all while auto-recharge is on and healthy? They are informational here; we could suppress them.
  3. Can view-only members be alert recipients, and can external addresses be added (the prototype allows both)?
  4. Metered overage alerts: fixed amounts only, or also a percentage of the commitment?
  5. How are credit codes positioned for Contracting and Metered customers? The prototype keeps Apply credit code under Grants for admins.
